30. Глоссарий

venv

Virtual Environment — изолированная папка с Python-зависимостями, не засоряет системный Python.

nvm

Node Version Manager — менеджер версий Node.js, устанавливается в ~/.nvm без sudo.

DRF

Django REST Framework — библиотека для создания REST API. Даёт сериализаторы, viewsets, permissions.

JWT

JSON Web Token — самодостаточный токен с подписью. Состоит из header, payload, signature.

CORS

Cross-Origin Resource Sharing — правила, разрешающие браузеру делать запросы между доменами.

SPA

Single Page Application — одностраничное приложение. React загружает HTML один раз, дальше меняет DOM.

Прокси

Промежуточный сервер. Vite проксирует /api на Django — обход CORS в разработке.

Middleware

Прослойка обработки запроса в Django. Срабатывает до view и после.

Serializer

DRF-класс, конвертирующий объекты Python ↔ JSON. Также валидирует входящие данные.

ViewSet / GenericView

Классы представлений DRF. Generic — на каждое действие свой класс. ViewSet — всё в одном.

CBV (Class-Based Views)

Представления Django в виде классов. Дают наследование, миксины и переиспользование. В коде гайда: ListCreateAPIView, RetrieveUpdateDestroyAPIView — всё это CBV из DRF. Противоположность — FBV (function-based views), обычные функции.

Интерцептор

Функция axios, срабатывающая до или после каждого запроса. Мы используем для JWT.

ORM

Object-Relational Mapping. Django ORM превращает Python-классы в SQL-таблицы.

Миграция

Файл с описанием изменений схемы БД. Создаётся makemigrations, применяется migrate.

Queryset

Ленивый запрос к БД в Django. Не выполняется, пока не обратитесь к данным.

Rootless Docker

Docker, работающий без root. Можно запускать контейнеры без sudo на РЕД ОС.

Хук (React Hook)

Функция вроде useState, useEffect — добавляет состояние и жизненный цикл в функциональные компоненты.

Bootstrap 5

CSS-фреймворк с готовыми компонентами. Их можно копировать с официального сайта и вставлять в шаблоны Django — сайт собирается как конструктор.

django_bootstrap5

Python-пакет, который подключает Bootstrap 5 к Django-шаблонам тегами {% bootstrap_css %} и {% bootstrap_javascript %}. Ставится командой pip install django-bootstrap5.

models.py

Файл приложения Django с классами-моделями на Python. Каждый класс — таблица в базе данных; из него по командам makemigrations и migrate создаётся реальная БД.

Django Admin

Готовая панель управления (/admin/), которую Django генерирует из моделей. Включается createsuperuser + регистрация модели в admin.py.

PostgreSQL

Мощная открытая СУБД для продакшена. В Django подключается пакетом psycopg и 5 строками в DATABASES — код моделей не меняется.

Gunicorn (WSGI)

Продуктивный WSGI-сервер для Python-приложений. Заменяет учебный runserver; запускают обычно за nginx: gunicorn backend.wsgi:application.

Reverse-proxy (nginx)

Сервер-посредник перед приложением: принимает HTTP/HTTPS, раздаёт статику и проксирует динамические запросы на gunicorn.

Preflight (OPTIONS)

Служебный запрос браузера перед «непростым» CORS-запросом: спрашивает сервер, разрешены ли метод и заголовки.

30. Глоссарий

venv

Virtual Environment — изолированная папка с Python-зависимостями, не засоряет системный Python.

nvm

Node Version Manager — менеджер версий Node.js, устанавливается в ~/.nvm без sudo.

DRF

Django REST Framework — библиотека для создания REST API. Даёт сериализаторы, viewsets, permissions.

JWT

JSON Web Token — самодостаточный токен с подписью. Состоит из header, payload, signature.

CORS

Cross-Origin Resource Sharing — правила, разрешающие браузеру делать запросы между доменами.

SPA

Single Page Application — одностраничное приложение. React загружает HTML один раз, дальше меняет DOM.

Прокси

Промежуточный сервер. Vite проксирует /api на Django — обход CORS в разработке.

Middleware

Прослойка обработки запроса в Django. Срабатывает до view и после.

Serializer

DRF-класс, конвертирующий объекты Python ↔ JSON. Также валидирует входящие данные.

ViewSet / GenericView

Классы представлений DRF. Generic — на каждое действие свой класс. ViewSet — всё в одном.

CBV (Class-Based Views)

Представления Django в виде классов. Дают наследование, миксины и переиспользование. В коде гайда: ListCreateAPIView, RetrieveUpdateDestroyAPIView — всё это CBV из DRF. Противоположность — FBV (function-based views), обычные функции.

Интерцептор

Функция axios, срабатывающая до или после каждого запроса. Мы используем для JWT.

ORM

Object-Relational Mapping. Django ORM превращает Python-классы в SQL-таблицы.

Миграция

Файл с описанием изменений схемы БД. Создаётся makemigrations, применяется migrate.

Queryset

Ленивый запрос к БД в Django. Не выполняется, пока не обратитесь к данным.

Rootless Docker

Docker, работающий без root. Можно запускать контейнеры без sudo на РЕД ОС.

Хук (React Hook)

Функция вроде useState, useEffect — добавляет состояние и жизненный цикл в функциональные компоненты.

Bootstrap 5

CSS-фреймворк с готовыми компонентами. Их можно копировать с официального сайта и вставлять в шаблоны Django — сайт собирается как конструктор.

django_bootstrap5

Python-пакет, который подключает Bootstrap 5 к Django-шаблонам тегами {% bootstrap_css %} и {% bootstrap_javascript %}. Ставится командой pip install django-bootstrap5.

models.py

Файл приложения Django с классами-моделями на Python. Каждый класс — таблица в базе данных; из него по командам makemigrations и migrate создаётся реальная БД.

Django Admin

Готовая панель управления (/admin/), которую Django генерирует из моделей. Включается createsuperuser + регистрация модели в admin.py.

PostgreSQL

Мощная открытая СУБД для продакшена. В Django подключается пакетом psycopg и 5 строками в DATABASES — код моделей не меняется.

Gunicorn (WSGI)

Продуктивный WSGI-сервер для Python-приложений. Заменяет учебный runserver; запускают обычно за nginx: gunicorn backend.wsgi:application.

Reverse-proxy (nginx)

Сервер-посредник перед приложением: принимает HTTP/HTTPS, раздаёт статику и проксирует динамические запросы на gunicorn.

Preflight (OPTIONS)

Служебный запрос браузера перед «непростым» CORS-запросом: спрашивает сервер, разрешены ли метод и заголовки.

from django import forms
from django.contrib.auth.models import User
from django.contrib.auth.forms import UserCreationForm, AuthenticationForm


class RegisterForm(UserCreationForm):
    """Регистрация: имя пользователя, e-mail и пароль дважды."""
    email = forms.EmailField(required=True, label='Электронная почта')

    class Meta:
        model = User
        fields = ('username', 'email', 'password1', 'password2')

    def save(self, commit=True):
        user = super().save(commit=False)
        user.email = self.cleaned_data['email']
        if commit:
            user.save()
        return user


class LoginForm(AuthenticationForm):
    """Вход: стандартная проверка Django, поля в стиле Bootstrap."""
    username = forms.CharField(widget=forms.TextInput(
        attrs={'class': 'form-control', 'placeholder': 'Логин'}))
    password = forms.CharField(widget=forms.PasswordInput(
        attrs={'class': 'form-control', 'placeholder': 'Пароль'}))

python# main/views.py — заменить содержимое целиком
from django.contrib import messages
from django.contrib.auth import login, logout
from django.contrib.auth.decorators import login_required
from django.shortcuts import redirect, render

from .forms import LoginForm, RegisterForm


def home(request):
    """Главная страница."""
    return render(request, 'home.html')


def register(request):
    """Регистрация: показали форму — GET, проверили и сохранили — POST."""
    if request.user.is_authenticated:
        return redirect('home')
    form = RegisterForm(request.POST or None)
    if request.method == 'POST' and form.is_valid():
        user = form.save()
        login(request, user)                 # сразу пускаем внутрь
        messages.success(request, 'Добро пожаловать, ' + user.username + '!')
        return redirect('home')
    return render(request, 'register.html', {'form': form})


def login_view(request):
    """Вход по логину и паролю."""
    if request.method == 'POST':
        form = LoginForm(data=request.POST)
        if form.is_valid():
            login(request, form.get_user())
            # после входа: на страницу, с которой пользователя сюда прислали (next),
            # иначе — в личный кабинет (/profile/). Про «next» см. шаг 8.
            return redirect(request.GET.get('next', '/profile/'))
    else:
        form = LoginForm()
    # отдаём шаблону next — форма входа сохранит его и вернёт пользователя
    # туда, откуда он пришёл (например, в кабинет или в корзину)
    return render(request, 'login.html', {'form': form, 'next': request.GET.get('next', '')})


@login_required                # без входа сюда не пустят
def profile(request):
    """Личный кабинет."""
    return render(request, 'profile.html', {'user_obj': request.user})


def logout_view(request):
    """Выход из аккаунта."""
    logout(request)
    return redirect('home')

python# main/cart.py — новый файл, помощники корзины
from decimal import Decimal

from .models import Product

CART_KEY = 'cart'


def cart_add(request, product_id, qty=1):
    """Положить товар в корзину (или увеличить количество)."""
    cart = request.session.setdefault(CART_KEY, {})
    key = str(product_id)
    cart[key] = cart.get(key, 0) + qty
    request.session.modified = True


def cart_items(request):
    """Список позиций для шаблона: товар, кол-во, сумма, итог."""
    cart = request.session.get(CART_KEY, {})
    items, total = [], Decimal('0')
    for pid, qty in list(cart.items()):
        product = Product.objects.filter(pk=pid).first()
        if not product:
            continue
        line = product.price * qty
        total += line
        items.append({'product': product, 'qty': qty, 'line_total': line})
    return items, total


def cart_clear(request):
    request.session[CART_KEY] = {}
    request.session.modified = True

Оффлайн: если пропадёт интернет, Bootstrap продолжит работать

Короткий ответ: по умолчанию — нет. Тег {% bootstrap_css %} пакета django_bootstrap5 вставляет ссылку на файлы Bootstrap с интернета (CDN): cdn.jsdelivr.net/npm/bootstrap@5.3.8/.../bootstrap.min.css и .../bootstrap.bundle.min.js. Без сети страницы перестанут быть красивыми (исчезнут стили), хотя регистрация, вход и данные никуда не денутся. Решается один раз за 2 минуты: скачиваем те же самые официальные файлы и кладём в папку static/ своего проекта.

Шаг O1. Скачиваем Bootstrap один раз (когда интернет есть)

bash# переходим к корню проекта (там, где manage.py)
cd путь/до/вашего/проекта

# создаём папки для статики: css и js
mkdir -p static/css static/js

# вариант 1: скачать готовые файлы напрямую по прямым ссылкам
curl -L -o static/css/bootstrap.min.css \
  https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css
curl -L -o static/js/bootstrap.bundle.min.js \
  https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js

# вариант 2 (если curl нет): скачать одним архивом и распаковать нужные файлы
curl -L -o /tmp/bootstrap.zip \
  https://github.com/twbs/bootstrap/releases/download/v5.3.8/bootstrap-5.3.8-dist.zip
python -c "import zipfile; z=zipfile.ZipFile('/tmp/bootstrap.zip'); \
z.extract('bootstrap-5.3.8-dist/css/bootstrap.min.css','/tmp'); \
z.extract('bootstrap-5.3.8-dist/js/bootstrap.bundle.min.js','/tmp')"
cp /tmp/bootstrap-5.3.8-dist/css/bootstrap.min.css static/css/
cp /tmp/bootstrap-5.3.8-dist/js/bootstrap.bundle.min.js static/js/

# проверка: оба файла на месте и «весят» больше 100 КБ
ls -lh static/css static/js

Что делать: откройте терминал в папке проекта (рядом с manage.py) и выполните команды из блока выше — они видны всегда, даже когда код скрыт. Проще всего скопировать в браузер адрес https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css и сохранить страницу как файл bootstrap.min.css, то же самое сделать со ссылкой на bootstrap.bundle.min.js. Положите эти два файла в проекте в папки static/css/ и static/js/ (создайте их, если их нет).

Bootstrap — это просто один CSS-файл и один JS-файл. Пока они лежат у вас в проекте, внешний вид сайта не зависит от интернета.

Шаг O2. Указываем django_bootstrap5 использовать локальные файлы

python# config/settings.py — добавьте в самый конец файла.
# Теперь {% bootstrap_css %} и {% bootstrap_javascript %}
# подключат Bootstrap из папки static/, а не из интернета.

BOOTSTRAP5 = {
    # локальный CSS вместо CDN (путь относительный, без слэша в начале)
    "css_url": {
        "url": STATIC_URL + "css/bootstrap.min.css",
    },
    # локальный JS вместо CDN
    "javascript_url": {
        "url": STATIC_URL + "js/bootstrap.bundle.min.js",
    },
    # integrity/crossorigin (подпись безопасности) для локальных файлов не нужна
    "theme_url": None,
}

# подсказка: значение по умолчанию STATIC_URL = "/static/" уже стоит
# в settings.py, так что получится "/static/css/bootstrap.min.css" —
# именно туда Django отдаст ваш файл.

Что делать: откройте файл config/settings.py, прокрутите в самый конец и допишите блок настроек BOOTSTRAP5 = {...} из карточки (в режиме «с кодом» — скопируйте готовый блок). Эти четыре строки говорят библиотеке django_bootstrap5: «бери Bootstrap не из интернета, а из твоей папки static». Больше ничего менять не нужно — шаблоны остаются как есть.

Настройки пакета django_bootstrap5 читаются из settings.py автоматически. Ключи css_url и javascript_url заменяют ссылки на CDN путями вашего проекта.
